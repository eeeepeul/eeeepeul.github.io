# 집 평면도 코드 기반 픽셀 렌더러 설계

## 목적

`/second/` 집 배경을 런타임 이미지 파일이 아닌 코드 기반 픽셀 렌더러로 교체한다. 현재 평면도의 방 배치, 가구 배치, 문·창문 위치와 색상 구성을 유지하면서 파란 벽을 시각적으로 더 얇게 만들고, 확대 시 흐릿한 래스터 이미지가 보이지 않도록 한다.

캐릭터가 파란 벽을 통과하지 못하는 동작은 기존 `HOUSE_INTERIOR_MAP`의 충돌 셀과 내비게이션을 계속 사용한다. 시각 표현과 충돌 판정은 별도 데이터로 유지한다.

## 범위와 불변 조건

- 통합 위치는 기존 `/second/` playfield의 배경 레이어로 한정한다.
- 기존 `/`, `/second/`, `/experience/` 라우팅, 사이드바, 캐릭터 레이어, 카메라 동작은 변경하지 않는다.
- `HOUSE_INTERIOR_MAP`의 64×48 논리 좌표, 방 범위, 문 개구부, 가구 충돌 셀, 스폰 위치는 변경하지 않는다.
- 캐릭터가 파란 벽을 넘어가지 못하는 `HOUSE_INTERIOR_COLLISION_CELLS`와 `createInteriorNavigation`의 계약은 유지한다.
- 런타임 배경에는 `house-interior-plan*.png`를 사용하지 않는다. 최종 시각 데이터는 코드 모듈로 보관한다.
- 새 렌더러가 표현하는 벽은 기존보다 얇은 고정 두께를 사용한다. 얇아지는 것은 시각 표현만이며 충돌 영역은 그대로다.

## 추천 접근: 코드 기반 픽셀 캔버스

현재 타일맵의 `HouseInteriorTilemap` 컴포넌트 인터페이스는 유지하고, 이미지 `<img>` 대신 하나의 `<canvas>`를 배경으로 렌더링한다. 캔버스는 논리 픽셀 좌표계에서 코드로 정의된 색상 런(run)과 사각형 명령을 그린다.

새 `lib/house-interior-pixel-art.mjs` 모듈은 다음을 노출한다.

- `HOUSE_INTERIOR_PIXEL_WIDTH`, `HOUSE_INTERIOR_PIXEL_HEIGHT`: 평면도의 기준 픽셀 크기
- `HOUSE_INTERIOR_PIXEL_PALETTE`: 바닥, 벽, 파란 보조색, 빨간 포인트, 흰색 등 제한된 팔레트
- `HOUSE_INTERIOR_PIXEL_RUNS`: 같은 색의 연속 도트를 `{ color, x, y, length }`로 묶은 불변 배열
- `HOUSE_INTERIOR_WALL_THICKNESS`: 시각 벽 두께를 한 곳에서 조절하는 상수

`HouseInteriorTilemap`은 클라이언트 효과에서 캔버스 컨텍스트를 초기화하고 `imageSmoothingEnabled = false`로 둔 뒤 픽셀 런을 `fillRect`로 그린다. CSS에서는 캔버스를 타일맵 전체에 절대 배치하고 현재 카메라 월드의 크기에 맞춰 확대한다. 캔버스의 비율은 원본 평면도와 동일하게 유지하며, 픽셀 보간은 사용하지 않는다.

픽셀 런 데이터는 기존 평면도의 시각 구성을 코드로 옮긴 결과물이다. 즉, 원본 PNG를 브라우저에서 읽거나 CSS 배경으로 참조하지 않고, 벽과 가구의 모든 보이는 도트를 코드가 직접 그린다. 방·문·가구의 논리 위치는 `HOUSE_INTERIOR_MAP`과 같은 좌표 계약을 사용해 충돌과 시각 위치가 분리된 채 동기화된다.

## 컴포넌트와 데이터 흐름

1. `HouseInteriorWorld`는 기존처럼 `HouseInteriorTilemap`과 전경 `FollowingCharacterWorld`를 같은 카메라 월드에 둔다.
2. `HouseInteriorTilemap`은 코드 기반 픽셀 캔버스, 기존 레이어 메타데이터, 숨은 `collision`·`spawn_points` 컨테이너를 렌더링한다.
3. `FollowingCharacterWorld`는 기존 `HOUSE_INTERIOR_MAP`을 받아 같은 충돌 셀에서 이동한다.
4. 캔버스는 표시 전용이며 포인터 이벤트를 받지 않는다. 이동 및 카메라 로직은 캔버스에 의존하지 않는다.

## 벽 두께와 시각 규칙

- 벽은 하나의 `HOUSE_INTERIOR_WALL_THICKNESS` 상수로 관리한다.
- 초기 목표는 현재 이미지의 벽보다 약 15~25% 얇은 시각 두께다.
- 벽을 얇게 그려도 문 개구부의 논리 셀과 충돌 셀은 기존 값을 유지한다.
- 기존의 흰 바닥, 짙은 파란 벽, 파란 보조 오브젝트, 빨간 포인트 색상과 평면도 방향을 유지한다.
- 새 렌더러는 외부 정원·연못·숲·추가 오브젝트를 만들지 않는다.

## 오류 처리와 호환성

- 캔버스가 지원되지 않거나 그리기 효과가 실행되지 않는 환경에서는 현재 타일맵의 단색 레이어를 안전한 시각 fallback으로 표시한다.
- 서버 정적 렌더링에서는 캔버스 요소와 접근성 메타데이터만 출력하며, 클라이언트 효과가 픽셀을 그린다.
- 캔버스 크기가 0인 초기 프레임에서도 예외를 던지지 않고 다음 레이아웃 프레임에서 다시 그릴 수 있게 한다.
- 기존 충돌·내비게이션 모듈에는 새 의존성을 추가하지 않는다.

## 검증 기준

- `HouseInteriorTilemap`에 배경 이미지 참조가 없고 코드 기반 픽셀 캔버스가 렌더링된다.
- 픽셀 데이터와 팔레트가 불변 코드 모듈로 존재하며 벽 두께 상수가 노출된다.
- 64×48 맵 계약, 방 범위, 문 개구부, 충돌 셀, 스폰 지점 테스트가 그대로 통과한다.
- 벽 두께 변경은 시각 픽셀 데이터에만 영향을 주고 `HOUSE_INTERIOR_COLLISION_CELLS`에는 영향을 주지 않는다.
- 기존 캐릭터 커스터마이징·NPC·카메라·사이드바 기능이 유지된다.
- 관련 테스트, 정적 빌드, 브라우저 `/second/` 미리보기를 확인한다.

## 이번 단계에서 하지 않는 것

키보드 이동 재작성, 충돌 알고리즘 변경, 새 방·가구 추가, 타일맵 좌표 재설계, 외부 이미지 다운로드, 다른 라우트의 배경 변경은 포함하지 않는다.
